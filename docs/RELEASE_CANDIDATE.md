# Project Hope v1.0.0-alpha.1 — Release Candidate

## Release intent

This candidate establishes the first coherent v1 architecture for Project Hope: a purely simulation-focused, memory-only platform with user-controlled JSON output, deterministic state, explicit accessibility timing, personhood safeguards and a React-based adaptive ICU interface.

## Candidate gates

### Required before merge
- GitHub Actions tests pass.
- Vite production build passes.
- Vercel Preview is deployable and visually inspected.
- Keyboard path covers Start, pause/resume, AAC composition/restore, decision selection, station progression, JSON export and discard.
- Screen-reader labels expose clinical/evaluation clocks and status changes.
- Large-text mode reflows without horizontal-only navigation.
- Reduced-motion and low-sensory modes remain functional.
- No code path writes simulation state to a database, localStorage or IndexedDB.
- Rohan scenario never invents a patient response from silence, gaze, movement or failed access.
- Personhood Guardian never produces a numeric personhood/quality-of-life score.

### Clinical/product boundary
- Fictional synthetic scenarios only.
- No real-patient record ingestion.
- No autonomous diagnosis/treatment authority.
- No medication doses, ventilator settings or procedural technique generated by the runtime.
- Research/evidence adapters remain read-only proposals until reviewed into a versioned rule pack.

## Known alpha limitations

- Clinical physiology is still scenario/rule driven rather than a validated high-fidelity physiologic digital twin.
- Current React UI uses the existing stylised ICU scene; documentary-realistic scene generation remains a separate media layer.
- External clinical evidence adapters (AMBOSS, Glass, Google Health/MedGemma) are not enabled in the runtime.
- Visual Truth is planned as a development-only visual editing workflow after the React shell is verified.
- Formal disability-led lived-experience review, clinical governance review and security review remain release gates for training use beyond prototype research.

## Definition of v1 alpha success

A user can run a fictional disability-inclusive medical simulation, preserve patient communication and personhood during clinical pressure, inspect deterministic state and decisions, replay the ordered command log, and leave without the platform retaining the session — unless the user explicitly exports JSON to their own device.
